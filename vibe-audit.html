What this app is

Goal. Ship a dog-rescue fundraising site where promoters get personal donation QRs, donors give any amount on Stripe, and operators track visits, gifts, and 50% commissions from a PIN-gated admin console.

Who it is for. Public donors; promoters who join for a QR; operators who unlock the volunteer portal with a server-verified PIN.

Checks that fit. Public pages, join/admin forms, private admin accounts, Stripe payments, Supabase database, avatar uploads, first-party visit geolocation, Edge APIs, and a daily operator dashboard. Not needed: blog, marketing email, AI, native apps, password-choice UI for visitors, or visitor social feeds beyond promoter profiles.

Fix these first

  1. The session is not in local storage. Keep the Supabase access token in memory only (or an HttpOnly cookie via a backend), not in localStorage/sessionStorage, and adjust the login→admin handoff accordingly.
  2. A retry cannot create a second charge. Generate one idempotency id when the donor starts checkout, send it as Idempotency-Key on every create-checkout retry, and keep the button disabled while the request runs.
  3. A limit and its update happen together. Record payouts in one database step that checks remaining commission (conditional update/transaction) so a second request cannot spend the same owed balance twice.
  4. Account settings. Add an account settings view on the admin side where the operator can see and change the stored account details (at least recover/change PIN via a server flow).
  5. Password reset or equivalent. Add a server-side recovery path (expiring reset or provider magic link built from siteOrigin in config) so a locked-out operator can get back in without the old PIN.
  6. The payment processor allows this business. Complete the Stripe Dashboard business-category review in docs/stripe-business-category.md and record the confirmed category (or keep live charges off until Stripe approves).
  7. A way to report and remove user content. Add a short public report/copyright page with privacy@ or similar, say what content is not allowed, link it from the footer, and document how staff remove reported promoter content. If offered in the US, name a DMCA agent.

Missing

Security

The session is not in local storage

Missing

A token in local storage can be read by any script on the page. An HttpOnly cookie cannot.

Evidencejs/supabase-client.js configures Supabase auth storage: sessionStorage (storageKey pf-admin-auth). Access tokens are in web storage.

How to fixKeep the Supabase access token in memory only (or an HttpOnly cookie via a backend), not in localStorage/sessionStorage, and adjust the login→admin handoff accordingly.

Security

A retry cannot create a second charge

Missing

A second tap on a slow connection can create a second charge, or a second record.

Evidencecreate-checkout / donate.js fetch has no Idempotency-Key; retries can create multiple Checkout Sessions.

How to fixGenerate one idempotency id when the donor starts checkout, send it as Idempotency-Key on every create-checkout retry, and keep the button disabled while the request runs.

Security

A limit and its update happen together

Missing

Two requests at the same moment can each pass a check you make first and write second, and spend a one-time code, a balance, or a quota twice.

EvidenceCommission owed is computed in the client (admin.js) then a payouts row is inserted without an atomic DB check that remaining owed covers the amount — a double submit can over-record paid.

How to fixRecord payouts in one database step that checks remaining commission (conditional update/transaction) so a second request cannot spend the same owed balance twice.
